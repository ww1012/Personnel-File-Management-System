# 开发计划

## 1. 阶段与门槛

| 阶段 | 产出 | 进入条件 |
| --- | --- | --- |
| 需求整理 | 需求说明、页面清单、数据模型、开发计划 | 已完成需求确认 |
| Figma 设计 | 登录页、工作台、员工列表、我的资料及关键弹窗设计 | 使用页面清单作为依据 |
| 设计确认 | 确认记录 | 用户明确说出“前端方案确认，可以开发” |
| 前端开发 | Vue 页面、路由、真实 API 客户端 | 设计确认后 |
| 后端开发 | Spring Boot、内存 Repository、权限和业务接口 | 前端结构稳定后，可并行推进 |
| 前后端联调 | 登录、权限、业务流程、异常状态验证记录 | 两端可启动 |
| 验收 | 验收清单、测试记录、界面截图 | 核心业务通过联调 |
| 数据库交接 | Repository 接口说明、MySQL 表结构与迁移说明 | 交给负责持久化的组员 |

发送设计图、链接或修改意见本身不构成开发批准；必须有上述明确确认语句。

## 2. 环境与分工

- 前端：Vue 3、TypeScript、Vite、Element Plus。
- 后端：Java 21、Spring Boot、Maven。
- 当前 Java 与 Maven 已配置；Maven Wrapper 可在后端交付前补充，用于统一构建环境。
- MySQL 是数据库交接阶段的目标，不是需求、Figma 或前端设计的前置条件。
- 本人负责前端、接口、业务逻辑、角色权限与联调；组员负责后续 MySQL 接入、持久化和完善。

## 3. 验证原则

每次功能完成后验证可访问性、角色边界、接口状态码、字段限制和异常反馈。联调阶段禁止用前端硬编码数据伪装业务结果；应保存接口测试结果、关键流程截图和问题修复记录，供实训报告使用。
