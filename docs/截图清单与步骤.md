# 论文界面截图清单与操作步骤

> 用途：课设论文「系统实现」章节需 5–8 张关键界面截图（不宜过多）。本清单给出建议截图、**进入路径**与**操作步骤**，全部截图须来自真实后端接口（不能写死数据冒充）。
> 说明：下列路由/界面与已实现系统一致；统计卡为「员工总数 / 离职人数 / 部门数量 / 岗位总数」四项（与代码一致）。

## 一、前置条件

1. **启动后端（MySQL 持久化模式）**：必须固定 8080 且带 `mysql` profile，否则前端代理连不上。
   ```
   # 参考 memory/2026-10-05.md 的「java 直启 Maven」命令
   spring-boot:run -Dspring-boot.run.arguments=--server.port=8080 --spring.profiles.active=mysql
   ```
   验证：`curl http://localhost:8080/api/health` 返回 `{"status":"UP"}`。
2. **启动前端**：`frontend/` 下 `npm install` 后 `npm run dev`，访问 http://localhost:5173 。
3. **准备账号**：用种子管理员账号登录；另准备一个职员账号用于「我的资料」与权限验证截图。
4. **截图建议**：浏览器窗口最大化，截整页或仅内容区；每张图在论文中配 1–2 行文字说明（做了什么、结果如何）。

## 二、建议截图清单（共 8 张，可酌情取舍至 5–6 张）

| 编号 | 页面 / 路由 | 建议文件名 | 需展示内容 | 操作步骤 |
| --- | --- | --- | --- | --- |
| 1 | 登录页 `/login` | `01-登录页.png` | 账号/密码输入框、登录按钮；可顺带展示「账号或密码错误」提示 | 未登录直接访问系统，进入登录页；尝试错误密码观察提示（再正确登录） |
| 2 | 管理员工作台 `/admin/dashboard` | `02-工作台.png` | 4 张统计卡（员工总数/离职人数/部门数量/岗位总数）+ 部门人数分布**扇形图**（每块标注部门名与人数）+ 近期人事变动列表 | 管理员登录后默认进入工作台 |
| 3 | 员工列表 `/admin/employees` | `03-员工列表.png` | 顶部筛选区（关键词/部门/状态）+ 表格（工号/姓名/部门/岗位/状态/更新时间）+ 操作列（详情/编辑/调岗/离职） | 左侧「员工管理」进入；可先输入关键词点搜索再截 | 
| 4 | 调岗弹窗 | `04-调岗弹窗.png` | 当前部门/岗位（只读）+ 新部门/新岗位（**岗位随部门联动**）+ 变动时间（默认当前时间）+ 原因 | 员工列表「操作列 → 调岗」打开；选择某部门后观察岗位下拉只显示该部门岗位 |
| 5 | 岗位管理 `/admin/positions` | `05-岗位管理.png` | 岗位表格含「所属部门」列 + 顶部筛选栏（岗位名称模糊搜索 + 部门下拉）+ 搜索/重置 | 左侧「岗位管理」进入；在筛选栏输入名称并选择部门后点搜索 |
| 6 | 职员「我的资料」 `/employee/profile` | `06-我的资料.png` | 个人概览（姓名/工号/状态）+ 任职信息（部门/岗位/入职日期，只读）+ 联系资料 + 编辑联系资料入口 | 用**职员账号**登录，默认进入「我的资料」 |
| 7 | 权限验证（403/401） | `07-权限验证.png` | 职员访问员工列表等管理员接口返回 403；或停用账号后登录返回 401 | 用职员账号调用员工列表接口（或前端越权访问），截「无权限」页；另可截停用账号后登录提示 |
| 8 | 人事变动列表 `/admin/changes` | `08-人事变动.png` | 筛选区（员工关键词/类型/日期）+ 表格（时间精确到秒、变动前后、操作人）+ 倒序 | 左侧「人事变动」进入；可点开一条查看变动前后对比 |

> 取舍建议：编号 1、2、3、4、6 为**核心必截**；5、7、8 选 1–2 张补足到 5–8 张即可。

## 三、截图时的注意事项

- **数据真实性**：列表/统计/扇形图均来自后端实时计算；截前确保后端在运行且已落库（mysql profile）。
- **状态展示**：离职员工在员工列表以状态标识展示（仍可查看，不物理删除）；调岗/离职会生成变动记录，可在编号 8 验证。
- **联动效果**：编号 4 的重点是「选部门后岗位下拉只含该部门岗位」，截图前先选一个部门让联动可见。
- **权限**：编号 7 体现「后端校验，未登录 401 / 越权 403」，是评分中「软件功能达到设计要求」的有力佐证。
- 每个界面在论文中对应一小节文字（界面功能 + 关键交互 + 与需求/验收项 A0x 的对应关系）。

## 四、与验收项对应（便于论文「系统实现」叙述）

- 登录/角色进入 → A01；职员仅本人资料 → A02；工作台统计来自真实数据 → A03；
- 员工列表筛选/新增/编辑 → A04；调岗/离职专用流程 + 变动记录 → A05；
