# MySQL 数据库接入交接

## 当前实现与边界

默认模式为 `app.storage.mode: memory`，不需要也不会读取 MySQL 配置。当前会话存储已经遵循 Repository 形式：

| 文件 | 作用 |
| --- | --- |
| `backend/src/main/java/com/personnel/repository/SessionRepository.java` | 会话存取契约：保存、查询、按令牌删除、按账号删除。 |
| `backend/src/main/java/com/personnel/repository/InMemorySessionRepository.java` | 当前会话内存实现。 |
| `backend/src/main/java/com/personnel/repository/Repository.java`、`InMemoryRepository.java` | 后续员工等实体 Repository 的通用接口/内存基类。 |
| `backend/src/main/java/com/personnel/service/SessionService.java` | 会话业务层，通过 `SessionRepository` 发放、查询、撤销令牌。 |
| `backend/src/main/java/com/personnel/api/PersonnelController.java` | 当前员工、账号、部门、岗位、变动的内存集合与业务规则。 |

注意：员工、账号、部门、岗位、变动记录尚未拆分成独立 Repository；组员接手时应先抽取接口与内存实现，再提供 MySQL 实现，保持现有 API 语义不变。不得把文档中的 MySQL 示例误认为已接入。

## 数据表建议

| 表 | 核心字段 | 约束 |
| --- | --- | --- |
| `account` | username、password_hash、role、employee_id、enabled | username 唯一；employee_id 唯一且职员账号才可非空。 |
| `employee` | id、employee_no、name、phone、email、address、education、department_id、position_id、hire_date、status、created_at、updated_at | employee_no 唯一；部门、岗位外键非空。 |
| `department` | id、name、description、created_at、updated_at | name 唯一。 |
| `position` | id、name、description、created_at、updated_at | name 唯一。 |
| `personnel_change` | id、type、employee_id、before_department_id、before_position_id、after_department_id、after_position_id、occurred_at、reason、operator_username | 变动记录不可修改删除；所有部门/岗位 ID 保留为历史引用。 |
| `session_token`（可选） | token、username、issued_at、expires_at | 若需服务重启后登录态保留才建立；当前不持久化。 |

枚举：`role` 为 `ADMIN`/`EMPLOYEE`；`employee.status` 为 `ACTIVE`/`RESIGNED`；`personnel_change.type` 为 `ONBOARD`/`TRANSFER`/`RESIGNATION`；账号启用状态用 `enabled` 布尔值。日期 API 使用 `yyyy-MM-dd`，时间使用 ISO-8601 字符串。

## 查询和返回约定

- 员工列表：`keyword` 匹配工号、姓名、手机号；`departmentId`、`status` 可选；`page` 从 1 开始，`size` 为每页数量。
- 列表统一返回 `{ content, total, page, size }`；无结果返回空 `content` 和 `total: 0`。
- 业务失败：参数/关联错误 400，未登录 401，越权 403，唯一或引用冲突 409，不存在 404。
- 前端接口路径、字段名和状态码详见 [接口文档](接口文档.md)，迁移时必须兼容。

## 事务边界

以下操作必须在单个数据库事务内执行，任一步失败都回滚：

1. 新增员工：员工档案 + `ONBOARD` 变动记录。
2. 调岗：更新员工部门和岗位 + 写入前后值齐全的 `TRANSFER` 记录。
3. 离职：更新员工状态 + 写入 `RESIGNATION` 记录 + 停用关联账号 + 删除该账号全部会话。
4. 停用账号、重置密码、修改本人密码：更新账号 + 删除该账号全部会话。
5. 创建职员账号：账号唯一检查 + 员工存在、在职且未关联账号检查。

部门、岗位删除前必须同时检查当前员工引用和 `personnel_change` 历史引用。应由数据库外键和应用层业务错误共同保证。

## 密码、会话和安全

- `password_hash` 存 BCrypt 哈希，不保存、返回或打印明文密码。
- 停用、退出、重置密码、修改密码都要使旧令牌失效。
- 当前 `session_token` 为内存实现，后端重启后所有登录态失效；这是预期行为。
- 若 MySQL 持久化会话，须决定 TTL、清理任务与 credential version；未做该设计前，建议仍保留内存会话，重启要求重新登录。

## 切换步骤

1. 复制 `backend/src/main/resources/application-mysql.example.yml` 为 `application-mysql.yml`，填写本机凭据；该真实文件已被 `.gitignore` 忽略。
2. 在 `pom.xml` 增加 MySQL 驱动、JPA/JDBC 依赖；不得删除内存模式依赖和测试。
3. 抽取 `AccountRepository`、`EmployeeRepository`、`DepartmentRepository`、`PositionRepository`、`PersonnelChangeRepository` 接口和现有内存实现。
4. 编写 MySQL 实现，按 `app.storage.mode` 注入；默认仍为 `memory`，以保证未配置 MySQL 时能启动。
5. 执行下列验收清单和全套回归测试。
