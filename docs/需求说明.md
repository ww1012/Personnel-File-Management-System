# 人事管理系统需求说明

## 1. 项目范围

本系统用于小型组织维护员工档案、部门、岗位、人事变动和职员账号。角色为管理员、职员；两者共用账号密码登录页，角色由后端按账号确定。系统不提供公开注册。

本版不包含工资、考勤、招聘、请假、审批或文件上传，只使用虚构演示数据。

## 2. 角色与权限

| 功能 | 管理员 | 职员 |
| --- | --- | --- |
| 登录、退出、修改本人密码 | 是 | 是 |
| 工作台统计 | 是 | 否 |
| 员工查询、详情、新增、普通编辑 | 是 | 否 |
| 调岗、离职 | 是 | 否 |
| 部门与岗位管理 | 是 | 否 |
| 人事变动查询 | 是 | 否 |
| 职员账号创建、停用、重置密码 | 是 | 否 |
| 查看个人档案 | 否 | 是，仅本人 |
| 修改手机号、邮箱、联系地址、学历 | 否 | 是，仅本人 |

职员的姓名、工号、部门、岗位、入职日期、在职状态只能查看。职员档案归属必须由后端登录身份判定，不能接收前端提交的员工 ID。

## 3. 员工档案字段

| 字段 | 说明 | 管理员普通编辑 | 职员编辑 |
| --- | --- | --- | --- |
| 员工 ID | 系统内部唯一标识 | 只读 | 不展示或只读 |
| 工号 | 唯一业务编号 | 新增时填写，之后只读 | 只读 |
| 姓名 | 员工姓名 | 可编辑 | 只读 |
| 手机号、邮箱、联系地址、学历 | 联系资料 | 可编辑 | 可编辑，仅本人 |
| 部门、岗位 | 有效字典关联 | 仅调岗流程修改 | 只读 |
| 入职日期 | 入职日期 | 可编辑 | 只读 |
| 在职状态 | 在职/离职 | 仅离职流程修改 | 只读 |
| 创建时间、更新时间 | 审计字段 | 只读 | 不展示或只读 |

## 4. 核心业务规则

1. 登录账号和员工工号分别唯一；管理员账号在初始化数据中创建，职员账号由管理员创建并关联一个员工档案。
2. 一个员工档案最多关联一个职员账号，可暂时没有账号。职员账号必须关联在职员工。
3. 员工必须关联有效的部门和岗位；岗位是独立字典，不与部门绑定。
4. 员工档案不物理删除。离职流程将状态改为离职、记录人事事件，并停用关联职员账号及其旧登录凭证。
5. 调岗必须至少变更部门或岗位之一，写入变动前后信息、时间、原因和操作人。普通员工编辑不得改变部门、岗位和状态。
6. 被员工或历史记录引用的部门、岗位不得删除；删除失败须说明原因。
7. 同一次调岗或离职中的档案更新、历史记录和账号状态更新必须作为一个一致操作处理。
8. 密码使用 BCrypt 等成熟哈希算法保存，不明文保存、返回或写入日志。退出、停用、重置密码或修改密码后，旧登录凭证必须失效。
9. 后端独立执行身份、角色和数据范围检查；未登录返回 401，越权返回 403。前端菜单和按钮只作体验控制，不能替代后端限制。

## 5. 验收标准

| 编号 | 验收项 |
| --- | --- |
| A01 | 管理员和职员可使用同一登录页登录，系统按后端账号角色进入正确首页。 |
| A02 | 职员只能读取自己的档案，只能保存手机号、邮箱、地址和学历。 |
| A03 | 管理员工作台的四项统计、部门人数分布和近期变动由后端实际内存数据计算。 |
| A04 | 员工列表支持关键词、部门、状态筛选与分页；可新增、查看和编辑规定字段。 |
| A05 | 调岗、离职分别执行专用流程并生成可查询的人事变动记录；离职不删除档案。 |
| A06 | 部门、岗位支持新增、编辑、查询；有关联员工时不能删除。 |
| A07 | 管理员能创建、停用职员账号并重置其密码；失效凭证不能继续调用接口。 |
| A08 | 前端通过真实后端接口显示数据；刷新浏览器保留后端进程中的数据，重启后端恢复初始演示数据。 |
